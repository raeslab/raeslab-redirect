# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Jekyll site on GitHub Pages whose only job is to keep old `raeslab.org` URLs (printed in
published papers) resolving to their new homes. There is no application code, no build step
to run in CI, and no tests. GitHub Pages builds `docs/` on push to `main`.

## Architecture

Everything hinges on the [`jekyll-redirect-from`](https://github.com/jekyll/jekyll-redirect-from)
plugin, one of the few plugins GitHub Pages whitelists. It is enabled in `docs/_config.yml`.

- `docs/` is the published site root (Pages source = branch `main`, folder `/docs`). Files
  outside `docs/` (including this one and `README.md`) are not published.
- `docs/CNAME` holds `raeslab.org`, which is what makes this *project* site answer on the apex
  domain instead of appearing under `code.raeslab.org/raeslab-redirect/`. The org site
  (`raeslab/raeslab.github.io`) separately owns `code.raeslab.org` — the redirect targets.
  Do not remove or change `CNAME` without understanding that split.
- `docs/redirects/**/*.md` — one front-matter-only file per migrated resource, grouped into
  `companion/`, `ocean-interactome/`, `ocean-carbon-export/` and `software/`. `permalink` is
  the old path, `redirect_to` the new URL, and `redirect_from` lists alternate spellings
  (underscore vs hyphen folders, the `tablesW13.xlsx` missing-slash typo). The plugin
  generates `<permalink>/index.html` with a meta refresh, a JS redirect and a `canonical`
  link. Filenames and subfolders are cosmetic; **every `permalink` and `redirect_from` value
  must be unique across the whole site** or the build breaks. The full old→new table lives in
  `README.md`.

When adding redirects, two things are worth repeating because they were established by
measurement, not assumption:
- **Check the real old paths against the Internet Archive** rather than trusting the URL as
  printed in a paper (`http://web.archive.org/cdx/search/cdx?url=raeslab.org/companion*&fl=original&collapse=urlkey`).
  That is how `/software/QMP temporal` was shown to really be `/software/QMP_temporal/`.
- **GitHub Pages collapses duplicate slashes** before matching, so malformed printed URLs like
  `figures//W1.pdf` need no redirect of their own.
- Avoid `%` in a `permalink`; it is not safe to feed to Jekyll and risks breaking the build.
- Migrated data files are not served by the project Pages sites (those only publish `docs/`);
  the repos link to `github.com/raeslab/<repo>/raw/main/...`, so deep file redirects target
  raw URLs.
- `docs/index.html` — root redirect (front matter only, no `permalink` needed).
- `docs/404.html` — catch-all; a hand-written page styled to match the VIB `entityone` theme
  (no auto-redirect), offering the lab site and `code.raeslab.org`. It is served with an HTTP
  404 status, so search engines treat it as a dead end. Any URL that appears in print needs
  its own file in `docs/redirects/`, not the 404.
- `docs/assets/` — vendored fonts and images so the 404 page makes no external requests.
  Provenance, licences and the VIB colour tokens are in `docs/assets/README.md` (excluded
  from the build). **Headings deliberately do not use VIB's Degular**: it is a domain-locked
  Adobe Fonts licence that cannot be self-hosted or served from `raeslab.org`.

**The 404 page must reference assets with root-absolute paths (`/assets/...`).** It is served
for unknown paths at any depth (`/software/x/y/`), where relative URLs would resolve wrong.
The redirect pages themselves are generated by the plugin and need no assets.

GitHub Pages cannot issue real HTTP 301s; the instant meta refresh is the substitute and
Google treats it as permanent.

## Adding a redirect

Create `docs/redirects/<Tool>.md` containing only front matter:

```yaml
---
permalink: /software/BMT/
redirect_to: https://code.raeslab.org/BMT/
---
```

For an old file path (`/page.php`, `/downloads/tool.zip`) use the exact path as `permalink`.
To map several old URLs onto one target, add `redirect_from:` as a list alongside `permalink`.
Commit and push — Pages rebuilds in a minute or two (visible in the repo's **Actions** tab).

## Local preview (optional, needs Ruby)

```bash
cd docs
bundle init
bundle add github-pages --group jekyll_plugins
bundle exec jekyll serve
```

Then open <http://localhost:4000/software/BMIS/>. `Gemfile.lock`, `_site/` and `.jekyll-cache/`
are gitignored; `Gemfile`/`Gemfile.lock` are also excluded from the Jekyll build.

## Operational notes

- DNS (apex A/AAAA records to GitHub Pages, `www` CNAME) and the one-time Pages setup are
  documented in `README.md`. Never suggest touching the `code.raeslab.org` record — the
  redirects point at it.
- The whole scheme depends on `raeslab.org` staying registered.
